# اینستاگرام (دایرکت) با BoxAPI

کانال دایرکت اینستاگرام روی [باکس‌ای‌پی](https://boxapi.ir) (پلن رایگان).
مشتری در دایرکت پیام می‌دهد، همان مغز بات تلگرام جواب می‌دهد و سفارش هم داخل
همان گفتگو ثبت می‌شود. کد در `src/instagram/` است.

## چرا این‌طور طراحی شد

- **یک مغز، دو کانال.** پاسخ‌ها از همان `composeReply` / `resolveReply` /
  `clarifyProducts` و همان مراحل سفارش (`order-flow`) می‌آیند که تلگرام استفاده
  می‌کند. اگر روزی لحن یا منطق قیمت عوض شود، هر دو کانال با هم عوض می‌شوند.
- **مسیر تلگرام دست‌نخورده است.** `TelegramService` (۱۳۰۰+ خط، با سفارش و
  پرداخت و پاسخ فروشنده) بازنویسی نشد؛ به‌جایش سرویس اینستاگرام همان توابع
  مشترک را صدا می‌زند. ریسک تغییر در چیزی که کار می‌کند صفر می‌ماند.
- **یک صندوق ورودی.** گفتگوی اینستاگرام در همان جدول‌های
  `TelegramConversation`/`ChatMessage` ذخیره می‌شود با
  `chatId = "ig:<IGSID>"`. نتیجه: پنل «گفتگوها» بدون صفحه‌ی جدید، هم تلگرام و
  هم اینستاگرام را نشان می‌دهد و پاسخ فروشنده از همان‌جا به همان کانال می‌رود.
- **اعلان فروشنده همیشه در تلگرام.** اگر مشتری از اینستاگرام بیاید، اعلان
  «سؤال نیازمند پاسخ انسانی» و «سفارش تازه» در چت تلگرام فروشنده می‌نشیند. دو
  کانال اعلان یعنی فروشنده دو جا باید سر بزند.
- **توکن فقط سمت سرور.** هیچ endpointی مقدار توکن یا سکرت را برنمی‌گرداند؛ حتی
  ماسک‌شده. پنل فقط «ست شده / ست نشده» می‌بیند. مستندات BoxAPI هم صریح گفته
  توکن نباید در کد فرانت‌اند یا مخزن عمومی باشد.

## چه چیزی «پلتفرمی» است و چه چیزی «هر فروشگاه»

| | کجا | چرا |
| --- | --- | --- |
| `INSTAGRAM_API_KEY` | env (پلتفرم) | یک حساب باکس‌ای‌پی برای کل سرویس؛ اجازه‌ی ارسال از پیج هر فروشگاه |
| `INSTAGRAM_WEBHOOK_SECRET` | env (پلتفرم) | امضای webhook؛ مشترک بین همه‌ی پیج‌ها |
| `INSTAGRAM_LOGIN_URL` | env (پلتفرم) | لینک ورود اختصاصی حساب باکس‌ای‌پی (`instagram_oauth_url`) |
| `INSTAGRAM_BASE_URL` | env (پلتفرم) | آدرس API |
| **`account_id` پیج** | **دیتابیس، هر فروشگاه** | هر فروشگاه پیج خودش را دارد؛ فروشنده از پنل وصل می‌کند |
| نام کاربری/عکس/انقضای پیج | دیتابیس، هر فروشگاه | از `/service/accounts` هنگام اتصال خوانده می‌شود |

`account_id` **هرگز** در env نیست. نسخه‌ی اول این ماژول آن را از env می‌خواند؛
برای یک پنل چندفروشگاهی غلط بود چون همه‌ی فروشگاه‌ها مجبور می‌شدند یک پیج
مشترک داشته باشند (و یا پیام یک فروشگاه با پیج دیگری برود).

## راه‌اندازی

### ۱. یک‌بار برای کل سرویس (env)

از داشبورد BoxAPI → «اتصال و آدرس‌ها» و «اطلاعات دسترسی»:

| کلید | از کجا |
| --- | --- |
| `INSTAGRAM_API_KEY` | اطلاعات دسترسی → Access Token |
| `INSTAGRAM_WEBHOOK_SECRET` | اطلاعات دسترسی → Webhook Secret |
| `INSTAGRAM_LOGIN_URL` | داشبورد → لینک ورود اختصاصی (`instagram_oauth_url`) |
| `INSTAGRAM_BASE_URL` | پیش‌فرض `https://api.sendbox.chat/api/v1` |

```bash
npm run instagram:setup     # بررسی توکن + فهرست پیج‌های لاگین‌شده + آدرس webhook
```

### ۲. برای هر فروشگاه: اتصال پیج از پنل

فروشنده در «تنظیمات → دایرکت اینستاگرام»:

1. **باز کردن صفحه‌ی اتصال حساب** — همان لینک ورود پلتفرم؛ با حساب پیج خودش
   وارد می‌شود و اجازه می‌دهد.
2. **پیج را وصل کردم؛ بررسی کن** — سرور `GET /service/accounts` را می‌خواند و
   پیج‌های آزاد را نشان می‌دهد.
3. **همین است** — پیج انتخاب و روی `Channel.instagramAccountId` ذخیره می‌شود.

قواعد این مرحله (همه در `link()` پیاده شده و تست دارد):

- پیج باید واقعاً در فهرست حساب باکس‌ای‌پی باشد (یعنی لاگین شده).
- پیجی که به فروشگاه دیگری وصل است، **در فهرست دیده نمی‌شود** و وصل‌کردنش
  رد می‌شود؛ نام کاربری پیج فروشگاه‌های دیگر به پنل شما نمی‌رسد.
- هر فروشگاه یک پیج فعال دارد؛ وصل‌کردن پیج جدید جایگزین می‌شود و گفتگوهای
  قبلی می‌مانند (کلید گفتگو `ig:<IGSID>` است، نه شناسه‌ی پیج).
- تاریخ انقضای دسترسی ذخیره می‌شود؛ پنل زیر ۷ روز هشدار می‌دهد.
- قطع اتصال، فقط اتصال را برمی‌دارد؛ گفتگوها و سفارش‌ها باقی می‌مانند.

### ۳. یک‌بار: تنظیمات داشبورد BoxAPI

سه فیلد در بخش «تنظیمات سرویس» داشبورد BoxAPI یک‌بار پر می‌شوند و به همه‌ی
فروشگاه‌ها مربوط‌اند (فرم را از پنل BoxAPI → تنظیمات سرویس باز کنید):

| فیلد | مقدار درست | چرا |
| --- | --- | --- |
| دامنه | `https://forooshyar-lac.vercel.app` | دامنه‌ی پنل فروشنده |
| آدرس بازگشت پس از ورود | `https://forooshyar-lac.vercel.app/app/settings` | بعد از ورود اینستاگرام، فروشنده به همان صفحه‌ای برمی‌گردد که کارت اینستاگرام در آن است |
| آدرس Webhook | `https://forooshyar.onrender.com/webhooks/instagram` | آدرس API؛ باید `https` و از بیرون قابل دسترس باشد |

مسیر قدیمی `https://forooshyar-lac.vercel.app/dashboard/instagram-api-setting`
هم به‌عنوان یک ریدایرکت به `/app/settings` نگه داشته شده تا اگر این فیلد روی
مقدار قدیمی ماند، فروشنده به ۴۰۴ نخورد.

### ۴. یک‌بار: ثبت webhook

در داشبورد BoxAPI این آدرس را ذخیره کنید:

```
https://<دامنه-ی-api>/webhooks/instagram
```

روی Render خودکار از `RENDER_EXTERNAL_URL` ساخته می‌شود؛ در غیر این صورت
`PUBLIC_API_URL` را ست کنید. آدرس نهایی در پنل با دکمه‌ی «کپی» نمایش داده
می‌شود. آدرس باید `https` باشد (الزام BoxAPI).

پیام‌های هر پیج با `account_id` موجود در webhook به فروشگاه صاحبش مسیریابی
می‌شوند. پیام پیجی که به هیچ فروشگاهی وصل نیست **پردازش نمی‌شود** (نه پاسخ
خودکار، نه سفارش) و فقط در audit با اکشن `instagram.unrouted` ثبت می‌شود.

## شکل بدنه‌ی webhook و عیب‌یابی «دایرکت آمد ولی در سایت نیست»

BoxAPI همیشه `event_type: "messaging"` با `data.messaging[]` نمی‌فرستد؛ در لاگ
واقعی، پیام‌ها با `event_type: "action.send_message"` و بدنه‌ی تودرتو هم می‌آیند.
پس مسیر پردازش دو لایه است:

1. مسیر استاندارد: `data.messaging[]` (و `comments[]` برای کامنت).
2. اگر پیامی پیدا نشد، بدنه تا ۶ سطح عمیق گشته و هر شیئی که «فرستنده + متن/پیام»
   دارد نرمال می‌شود (`collectMessages`). رویدادهای بی‌متن (خوانده‌شد، تایپ)
   نادیده گرفته می‌شوند و اکوی پیام خود پیج پاسخ نمی‌گیرد.

بدنه‌ی هر رویداد (بریده‌شده) در جدول `InstagramEvent` ذخیره می‌شود و
`GET /instagram/events` خلاصه‌اش را برای همین فروشگاه برمی‌گرداند: نوع رویداد،
شمار پیام‌های شناسایی‌شده، اکو یا نه، و شناسه‌ی ماسک‌شده‌ی فرستنده. در کارت پنل،
اگر هیچ گفتگویی نباشد همین فهرست نمایش داده می‌شود تا مشخص شود:

| در فهرست رویدادها چه می‌بینید | معنا |
| --- | --- |
| `messaging · 1 پیام · فرستنده …` | پیام رسیده و پردازش شده؛ گفتگو باید در «گفتگوها» باشد |
| `action.send_message · بدون پیام · کلیدها: …` | شکل بدنه ناشناس بوده؛ کلیدها را برای پشتیبانی بفرستید |
| `… (اکو)` | پیام خودِ پیج/فروشنده است؛ طبیعی است که گفتگو نسازد |
| فهرست خالی («هنوز رویدادی نرسیده») | آدرس webhook در داشبورد BoxAPI ثبت نشده یا امضا رد می‌شود |

## قرارداد webhook

بدنه:

```json
{ "event_id": "…", "event_type": "messaging", "account_id": "<uuid>", "data": { "messaging": [ … ] } }
```

`event_type` های پشتیبانی‌شده:

| نوع | رفتار |
| --- | --- |
| `messaging` | مسیر کامل مشتری: مغز بات، سفارش، تأیید تحویل |
| `messaging_postbacks` | دکمه‌ها: `p:` محصول، `ord:` شروع سفارش، `flow:` مرحله‌ی سفارش، `cl:` رفع ابهام، `pg:` صفحه‌بندی، `watch:` خبر موجودی |
| `comments` | پاسخ عمومی فقط وقتی محصول پیدا شود؛ در غیر این صورت فقط ثبت |
| `mentions` و `action.*` | فقط ثبت در audit (پاسخ خودکار به mention اسپم است) |

امنیت (چهار لایه):

1. امضای HMAC-SHA256 روی **بدنه‌ی خام**:
   `HMAC_SHA256("{X-BoxApi-Timestamp}.{rawBody}", secret)` با پیشوند `sha256=` در
   هدر `X-BoxApi-Signature`. اگر JSON را دوباره سریالایز کنیم امضا هرگز
   نمی‌خواند؛ به همین دلیل `jsonBodyParser` فقط برای همین مسیر بافر خام را نگه
   می‌دارد.
2. مهر زمانی باید فقط رقم باشد و حداکثر ۳۰۰ ثانیه اختلاف داشته باشد.
3. مقایسه‌ی زمان‌ثابت (`timingSafeEqual`).
4. `event_id` در جدول `InstagramEvent` یکتاست؛ BoxAPI تا ۳ بار در ۶۰ ثانیه
   دوباره می‌فرستد و بدون این قفل، مشتری جواب تکراری می‌گرفت.

پاسخ همیشه `200` است (حتی وقتی پردازش شکست بخورد) تا BoxAPI رویداد را دور
نیندازد؛ پردازش بعد از تأیید امضا و **بدون انتظار** اجرا می‌شود تا پاسخ سریع
بماند.

## تفاوت‌های قالب با تلگرام

| تلگرام | اینستاگرام |
| --- | --- |
| HTML (`<b>`, `<i>`) | متن ساده؛ تگ‌ها حذف و موجودیت‌ها بازگردانی می‌شوند |
| دکمه‌ی inline نامحدود | حداکثر ۳ دکمه (عنوان ۲۰ کاراکتر) |
| — | بیش از ۳ گزینه → پاسخ سریع (تا ۱۳) |
| پیام بلند تکه‌تکه | سقف ۱۰۰۰ کاراکتر، برش روی مرز خط |

`src/instagram/format.ts` همین تبدیل‌ها را انجام می‌دهد و تست دارد.

## لاگ و audit

همه‌ی اقدام‌ها با پیشوند `instagram.` ثبت می‌شوند. نمونه: اتصال/قطع پیج
(`instagram.account_linked`، `instagram.account_unlinked`)، باز کردن لینک ورود
(`instagram.connect_link_opened`)، ارسال بدون پیج (`instagram.send_no_account`)،
`instagram.message`،
`instagram.order_created`، `instagram.order_started`، `instagram.send_failed`،
`instagram.comment_replied`، `instagram.account_linked`، `instagram.unrouted`،
`instagram.payload_ignored`، `instagram.not_configured`.

## عیب‌یابی

| نشانه | علت محتمل |
| --- | --- |
| درخواست‌ها ۴۰۱ می‌گیرند | سکرت اشتباه، یا ساعت سرور از BoxAPI بیش از ۵ دقیقه اختلاف دارد |
| پیام مشتری می‌آید ولی جوابی نمی‌رود | پیج به فروشگاه وصل نیست (`instagram.send_no_account`) یا `INSTAGRAM_API_KEY` ست نشده |
| `instagram.unrouted` در audit | پیج به هیچ فروشگاهی وصل نیست؛ فروشنده از پنل وصلش کند |
| webhook ثبت نمی‌شود | آدرس باید `https` باشد و از بیرون قابل دسترس |
| پاسخ در دایرکت با تگ `<b>` می‌آید | یعنی از مسیر تلگرام رفته؛ `send()` اینستاگرام را چک کنید |
| دایرکت می‌دهم ولی نه گفتگویی ساخته می‌شود نه رویدادی ثبت می‌شود | webhook ثبت نشده یا به آدرس دیگری می‌رود؛ لاگ Render باید `webhooks.create` نشان دهد |
| رویداد ثبت می‌شود ولی «بدون پیام» است | شکل بدنه ناشناس؛ کلیدهای خلاصه را برای پشتیبانی بفرستید (پردازش عمیق در `collectMessages` هست) |
| پنجره‌ی «اتصال حساب» سفید می‌ماند | لینک ورود باز نشده: `INSTAGRAM_LOGIN_URL` را در env چک کنید؛ پنل پنجره را کنترل‌شده باز می‌کند و اگر لینک نرسد خطای فارسی نشان می‌دهد |
| بعد از ورود اینستاگرام به ۴۰۴ می‌رسد | «آدرس بازگشت پس از ورود» در داشبورد BoxAPI قدیمی است؛ مقدار درست در بخش «تنظیمات داشبورد BoxAPI» |
| صفحه‌ی اتصال پیام `Invalid Instagram login token` می‌دهد | `INSTAGRAM_LOGIN_URL` منقضی/نادرست است؛ همان `instagram_oauth_url` تازه را از داشبورد بردارید |
