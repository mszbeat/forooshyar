# کاتالوگ‌های آماده برای تست

سه فایل آماده برای تست صفحهٔ **ورود کاتالوگ** (`/app/import`):

| فایل | چه چیزی را تست می‌کند | نتیجهٔ تست‌شده |
|---|---|---|
| `forooshyar-catalog-30.csv` | بارگذاری کامل و سالم | ۳۰ ردیف → ۳۰ محصول، ۰ خطا |
| `forooshyar-catalog-30.xlsx` | مسیر اکسل (اعداد واقعی سلولی) | ۳۰ ردیف → ۳۰ محصول، ۰ خطا |
| `forooshyar-import-errors-demo.csv` | گزارش خطای ردیفی | ۳ موفق، ۶ ناموفق (عمدی) |

همهٔ `sku`ها با پیشوند اختصاصی (`C30-` و `ERR-`) ساخته شده‌اند تا بتوانید فایل را در **همان فروشگاه
نمایشی** هم بدون خطای «کد کالای تکراری» بارگذاری کنید.

> هر سه فایل روی endpoint واقعی `POST /catalog/import` تست شده‌اند.

## چطور تست کنم؟

1. وارد پنل شوید → **ورود کاتالوگ**
2. فایل را با drag & drop یا کلیک انتخاب کنید → **شروع بارگذاری**
3. نتیجه را ببینید: تعداد موفق/ناموفق، و برای فایل خطادار، جدول «ردیف / وضعیت / توضیح خطا»

بعد از بارگذاری موفق، به **محصولات و موجودی** و **داشبورد** بروید: تعداد محصولات، ارزش انبار،
واریانت‌های کم‌موجود و ناموجود همه باید با فایل بخوانند.

> ⚠️ در یک فروشگاه هر SKU فقط یک‌بار قابل ثبت است. اگر همین فایل را دوباره در همان فروشگاه
> بارگذاری کنید، همهٔ ردیف‌ها با پیام «کد کالا تکراری است» رد می‌شوند — این رفتار درست است.
> برای تست دوباره، یا `sku`ها را تغییر دهید یا با ایمیل دیگری فروشگاه تازه بسازید.

## ردیف‌های خطادار در فایل خطا (همه عمدی)

| ردیف | مشکل | پیام دریافتی |
|---|---|---|
| ۳ | نام محصول خالی | `title: String must contain at least 1 character(s)` |
| ۴ | قیمت متنی (`گران`) | `price: Expected number, received null` |
| ۵ | قیمت منفی | `price: Expected number, received null` |
| ۶ | موجودی اعشاری (`2.5`) | `stock: Expected number, received null` |
| ۷ | `sku` تکراری با ردیف ۲ | `SKU already exists in this shop` |
| ۹ | ردیف خالی | (بی‌صدا رد می‌شود — درست است) |

| ۱۰ | نام بیش از ۲۰۰ کاراکتر | `title: String must contain at most 200 character(s)` |
| ۲ و ۸ و ۱۱ | ردیف سالم (ردیف ۸ با اعداد فارسی و `٬`) | ✅ ثبت می‌شود |

## قواعد ایمپورتر (از `backend/src/imports/import.service.ts`)

- **ستون‌های شناسایی‌شده:** `title` / `name` / `نام` / `نام محصول` · `price` / `قیمت` · `stock` / `موجودی` · `size` / `سایز` · `color` / `رنگ` · `sku`
  - هر ستون دیگری (مثل `category`) **نادیده** گرفته می‌شود؛ به همین دلیل در راهنمای داخل پنل هم
    نمایش داده نمی‌شود، هرچند اگر در فایل باشد خطا ایجاد نمی‌کند.
  - `title`، `price` و `stock` الزامی‌اند و نباید تکراری باشند.
- **قیمت و موجودی:** عدد صحیح نامنفی. اعداد فارسی/عربی، `٬` و `,` و فاصله داخل عدد پذیرفته می‌شود (`۱۲٬۵۰۰٬۰۰۰` هم درست است).
- **`sku`:** اختیاری، ولی در هر فروشگاه یکتا.
- **هر ردیف = یک محصول جدید با یک واریانت.** ایمپورتر محصولات هم‌نام را ادغام نمی‌کند؛ برای
  یک محصول با چند سایز، بعد از ایمپورت از دکمهٔ **سایز / رنگ** استفاده کنید.
- **محدودیت‌ها:** حداکثر ۲ مگابایت، ۱۰۰۰ ردیف، ۲۰ ستون، UTF-8 (BOM مجاز است). فرمول و سلول‌های
  غیرمتنی در اکسل رد می‌شوند (به دلایل امنیتی ارزیابی نمی‌شوند).
- **موجودی اولیه:** هر ردیف با `stock > 0` یک گردش با دلیل `import` در دفتر گردش ثبت می‌کند.

## بازتولید فایل‌ها

```bash
cd catalogs
python3 build-catalogs.py          # CSV + XLSX (برای XLSX نیاز به pip install openpyxl)
node verify.mjs                    # تست هر سه فایل روی API واقعی (نیاز به API روشن روی :3001)
```

`verify.mjs` برای هر فایل یک فروشگاه موقت می‌سازد تا با داده‌های فروشگاه نمایشی قاطی نشود.

## نکتهٔ Excel

فایل CSV با **UTF-8 + BOM** ساخته شده تا Excel فارسی را به‌هم نریزد؛ اگر خودتان فایل می‌سازید و
Excel متن را نامفهوم نشان می‌دهد، فایل را «CSV UTF-8» ذخیره کنید.
