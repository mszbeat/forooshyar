# پنل ادمین پلتفرم

جای تنظیمات حساس سامانه: مدل زبانی، توکن ربات، درگاه پرداخت، اتصال دیتابیس و
پرچم‌های سیستم — همه از مرورگر، بدون ویرایش فایل روی سرور.

> مرز مهم: پنل ادمین **داده‌ی فروشگاه‌ها را نشان نمی‌دهد و تغییر نمی‌دهد**.
> ادمین یک نقش جدا با جدول جداست؛ پنل فروشنده جای کار روزمره‌ی فروشنده است.

---

## ۱. ورود

آدرس: `/admin/login`

| | |
| --- | --- |
| ایمیل پیش‌فرض | `sadeghADM@forooshyar.com` |
| رمز پیش‌فرض | `s0a0d0e0g0h0` |
| اعتبار نشست | ۸ ساعت |

حساب ادمین در **اولین بالا آمدن سرویس** ساخته می‌شود (لاگ: `حساب ادمین ساخته شد`).
رمز فقط با scrypt هش و در جدول `PlatformAdmin` ذخیره می‌شود؛ هیچ‌جا متن رمز
نگه داشته نمی‌شود و در لاگ هم نوشته نمی‌شود.

### تغییر رمز

پنل ادمین → **حساب ادمین** → «تغییر رمز». رمز تازه حداقل ۱۰ کاراکتر.

### اگر رمز را گم کردید

۱. مقدار `ADMIN_EMAIL` را به یک ایمیل **تازه** و `ADMIN_PASSWORD` را به رمز
   دلخواه در متغیرهای محیطی سرور بگذارید.
۲. سرویس را ری‌استارت کنید. اگر آن ایمیل وجود نداشته باشد، ساخته می‌شود.
۳. وارد شوید و از صفحه‌ی «حساب ادمین» رمز را عوض کنید.

> ایمیل موجود بازنویسی **نمی‌شود** — عمدی است تا با یک متغیر محیطی قدیمی، رمز
> کسی به‌طور خاموش به مقدار پیش‌فرض برنگردد.

## ۲. صفحه‌ها

| صفحه | چه چیزی را کنترل می‌کند |
| --- | --- |
| **نمای کلی** | شمارش فروشگاه/محصول/سفارش، وضعیت سه سرویس (AI، BOT، DB)، دفتر گردش |
| **هوش مصنوعی** | انتخاب ارائه‌دهنده و مدل، کلید API، temperature، آزمون اتصال |
| **تلگرام و ربات** | توکن بات، سکرت webhook، آدرس Bot API و آزمون `getMe`/`getWebhookInfo` |
| **پرداخت** | شناسه‌ی پذیرنده‌ی زرین‌پال و آدرس API |
| **دیتابیس** | آدرس اتصال، وضعیت جاری، مهاجرت‌ها و **آزمون یک آدرس دیگر** |
| **سیستم و امنیت** | CORS، کش/Redis، لاگ گردش، ری‌استارت سرویس |
| **حساب ادمین** | هویت و تغییر رمز |

## ۳. اولویت مقدار تنظیمات

```
مقدار ذخیره‌شده در پنل  →  متغیر محیطی سرور  →  پیش‌فرض کد
```

* پنل بر env **اولویت** دارد؛ خالی‌کردن فیلد یعنی «برگرد به مقدار سرور».
* مقادیر حساس (کلیدها، توکن، سکرت) در پاسخ فقط **ماسک‌شده** برمی‌گردند
  (`••••mnop`). اگر فرم را بدون تغییر ذخیره کنید، مقدار واقعی دست‌نخورده
  می‌ماند (مقدار ماسک‌شده هرگز به‌عنوان مقدار تازه ذخیره نمی‌شود).
* تنظیمات هنگام **بالا آمدن سرویس** و **بلافاصله بعد از ذخیره** روی
  `process.env` اعمال می‌شوند.

### کدام تنظیم بلافاصله اثر می‌کند؟

| فوری | نیازمند ری‌استارت |
| --- | --- |
| مدل، کلید، temperature، سقف توکن | `DATABASE_URL` |
| توکن بات، سکرت webhook، آدرس Bot API | `CORS_ORIGINS` |
| شناسه‌ی پذیرنده‌ی زرین‌پال | `CACHE_ENABLED` / `REDIS_URL` |
| پرچم `DEBUG_CLARIFY` | `AUDIT_LOG_READS` |

«نیازمند ری‌استارت» یعنی مقدارش هنگام ساخت سرویس خوانده و قفل می‌شود. بعد از
ذخیره، بالای نمای کلی و در **سیستم و امنیت** دکمه‌ی «ری‌استارت سرویس» ظاهر
می‌شود (روی Render، خود پلتفرم سرویس را دوباره بالا می‌آورد).

## ۴. دستور پخت‌های کوتاه

### وصل‌کردن مدل زبانی

۱. **هوش مصنوعی** → یکی از کارت‌های ارائه‌دهنده (OpenAI، OpenRouter، Groq،
   مدل خودمیزبان) را بزنید — آدرس درگاه و نام مدل با هم پر می‌شوند.
۲. مدل دقیق را از فهرست انتخاب کنید.
۳. کلید را بچسبانید (درگاه محلی بدون کلید: `local`).
۴. **ذخیره** → دکمه‌ی «ارسال درخواست آزمایشی».
   نتیجه‌ی خوب: `اتصال برقرار شد` + زمان پاسخ.
۵. کنترل نهایی: پنل فروشنده → **دستیار پاسخ‌گو** → پرسش «گارانتی اصالت کالا
   دارید؟»؛ برچسب **«پاسخ مدل زبانی»** باید ظاهر شود.

### عوض‌کردن توکن ربات

۱. توکن تازه را در **تلگرام و ربات** ذخیره کنید.
۲. سکرت webhook را هم عوض کنید (حداقل ۱۶ کاراکتر) تا مسیر قدیمی بی‌اعتبار شود.
۳. پنل فروشنده → تنظیمات → تلگرام → **ثبت webhook**.
۴. در پنل ادمین «آزمون ربات» را بزنید: نام کاربری بات و آدرس webhook باید
   دیده شود و «در صف» صفر باشد.

### انتقال به دیتابیس دیگر

۱. ابتدا مهاجرت‌ها را روی مقصد اجرا کنید: `npm run prisma:deploy`.
۲. در **دیتابیس**، آدرس تازه را در «آزمون یک آدرس دیگر» بگذارید و **بدون
   ذخیره‌کردن** تست کنید.
۳. اگر اتصال برقرار شد، در فیلد `DATABASE_URL` ذخیره کنید.
۴. **ری‌استارت سرویس**.
۵. پیش از هر تغییر: `deploy/backup-db.sh`.

## ۵. امنیت

* **جدایی نقش‌ها:** توکن ادمین `kind: "admin"` دارد و `shopId` ندارد؛
  `AuthGuard` فروشنده آن را رد می‌کند. توکن فروشنده هم در `AdminGuard` رد
  می‌شود. دو نشست می‌توانند هم‌زمان در یک مرورگر باز باشند (کلیدهای
  `forooshyar.token` و `forooshyar.admin`).
* **کلیدهای غیرقابل‌تغییر از پنل:** `JWT_SECRET`، `PORT`، `HOST` و مسیر ساخت
  حساب ادمین. تلاش برای نوشتن کلید ناشناخته با ۴۰۰ رد می‌شود.
* **دفتر گردش:** هر ورود، تغییر تنظیمات و آزمون اتصال با اکشن‌های
  `admin.login`، `admin.settings_update`، `admin.ai_probe`، `admin.restart`
  ثبت می‌شود — بدون مقدار کلیدها.
* **محدودیت نرخ:** همان Throttler سراسری (۱۰۰ درخواست در دقیقه برای هر IP).

## ۶. API پنل ادمین

همه با `Authorization: Bearer <ADMIN_TOKEN>`، به‌جز ورود.

| متد | مسیر | کار |
| --- | --- | --- |
| POST | `/admin/auth/login` | ورود؛ خروجی `accessToken` |
| GET | `/admin/auth/me` | هویت ادمین |
| POST | `/admin/auth/password` | تغییر رمز (`current`, `next`) |
| GET | `/admin/overview` | شمارش‌ها، وضعیت سرویس‌ها، دفتر گردش |
| GET | `/admin/settings` | فهرست گروه‌ها و مقادیر (ماسک‌شده) |
| PUT | `/admin/settings` | ذخیره‌ی گروهی: `{ "values": { "AI_MODEL": "gpt-4o" } }` |
| POST | `/admin/diagnostics/ai` | یک درخواست واقعی به مدل |
| POST | `/admin/diagnostics/telegram` | `getMe` + `getWebhookInfo` |
| POST | `/admin/diagnostics/database` | آزمون `DATABASE_URL` (یا آدرس داده‌شده) |
| GET | `/admin/database` | نسخه، حجم، مهاجرت‌ها |
| POST | `/admin/restart` | خروج کنترل‌شده برای بالا آمدن دوباره |

### نمونه

```bash
TOKEN=$(curl -s -X POST localhost:10000/admin/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"sadeghADM@forooshyar.com","password":"s0a0d0e0g0h0"}' | jq -r .accessToken)

curl -s -X PUT localhost:10000/admin/settings -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"values":{"AI_ENABLED":"true","AI_BASE_URL":"https://api.openai.com/v1","AI_MODEL":"gpt-4o-mini","AI_API_KEY":"sk-..."}}'

curl -s -X POST localhost:10000/admin/diagnostics/ai -H "Authorization: Bearer $TOKEN"
```
