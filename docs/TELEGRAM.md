# اتصال فروشیار به تلگرام

ربات مشترک: **یک بات برای همه‌ی فروشگاه‌ها**. هر فروشگاه یک کد کوتاه دارد و لینک
`t.me/<bot>?start=<code>` را به مشتری‌هایش می‌دهد. مشتری که لینک را باز کند، وارد چت
همان فروشگاه می‌شود.

دو کاری که انجام می‌شود:

| برای | چه اتفاقی می‌افتد |
|---|---|
| **مشتری** | سؤال قیمت/موجودی/ارسال/پرداخت/ساعت کاری را می‌پرسد و جواب از داده‌ی واقعی همان فروشگاه می‌گیرد؛ هر جای نامطمئن، به فروشنده ارجاع داده می‌شود |
| **فروشنده** | اعلان فروش، هشدار موجودی کم، و سؤال‌هایی که به انسان ارجاع داده شده |

فلسفه‌ی پاسخ‌دهی همان `answerFresh` است که از قبل داشتیم — **هیچ حدسی نمی‌زند**.
اگر مطمئن نباشد، جواب نمی‌سازد؛ ارجاع می‌دهد.

---

## ۱. ساخت بات در BotFather (۵ دقیقه)

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بده.
2. `/newbot` را بفرست.
3. **نام نمایشی** بات را بنویس، مثلاً: `فروشیار`
   (این چیزی است که کاربر‌ها می‌بینند.)
4. **نام کاربری** بات را بنویس؛ باید یکتا باشد و به `bot` ختم شود، مثل:
   `forooshyar_support_bot`
5. BotFather یک توکن می‌دهد شبیه این:

   ```
   7123456789:AAH3xYz...        ← این را جایی امن نگه دار، مثل رمز عبور است
   ```

6. پیشنهادی ولی مفید — در BotFather:
   - `/setdescription` → توضیح کوتاه فروشگاه برای صفحه‌ی شروع بات
   - `/setuserpic` → لوگو
   - `/setcommands` → این متن را بفرست تا منوی بات ساخته شود:
     ```
     start - شروع گفتگو با فروشگاه
     help - راهنمای سؤال‌ها
     stop - بستن گفتگو
     link - اتصال چت فروشنده به فروشگاه
     ```

> اگر توکن لو رفت، در BotFather `/revoke` بزن و مقدار جدید را در سرور بگذار.

## ۲. پیکربندی سرور (Render)

در سرویس **API**، بخش Environment این سه متغیر را اضافه کن:

| متغیر | مقدار | توضیح |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | توکن BotFather | اجباری |
| `TELEGRAM_WEBHOOK_SECRET` | `openssl rand -hex 32` | هم در مسیر URL می‌آید هم در هدر؛ **حتماً تصادفی** |
| `PUBLIC_API_URL` | `https://forooshyar-api.onrender.com` | آدرس عمومی API، بدون اسلش انتهایی |

سپس یک‌بار (از Shell سرویس API در Render، یا لوکال با همان env ها):

```bash
npm run telegram:setup
```

خروجی موفق:

```
🤖 بات: @forooshyar_support_bot (فروشیار)
   وضعیت فعلی: بدون webhook

✔ webhook ثبت شد.
   URL      https://forooshyar-api.onrender.com/telegram/webhook/9f3c…
   لینک مشتری  https://t.me/forooshyar_support_bot?start=<کد فروشگاه>
```

بررسی وضعیت و خطاهای تلگرام:

```bash
npm run telegram:setup -- --info
npm run telegram:setup -- --delete   # حذف webhook
```

`--info` اگر خطایی بدهد، همان پیام تلگرام را نشان می‌دهد (مثلاً `Wrong response from the webhook: 401`).

> **چرا webhook و نه polling:** روی Render پلن Free سرویس پس از ۱۵ دقیقه بی‌کاری
> می‌خوابد. یک حلقه‌ی long-polling در چنین محیطی مرتب قطع/وصل می‌شود و پیام از دست
> می‌رود. در webhook، تلگرام پیام را push می‌کند و سرویس با همان پیام بیدار می‌شود.

## ۳. اتصال از پنل

**تنظیمات → اتصال به تلگرام**

1. **فعال‌سازی اتصال تلگرام** → یک لینک اختصاصی ساخته می‌شود.
2. لینک را کپی کن و در بیو اینستاگرام/پست/پیام بگذار.
3. برای اعلان‌ها: **ساخت کد اتصال** → کد را در چت بات بفرست (یا دکمه‌ی «باز کردن بات»).
   بعد از آن، چت تلگرام تو به فروشگاه وصل می‌شود و اعلان‌ها می‌آید.

از همان لحظه:

- مشتری: `t.me/<bot>?start=<code>` → سؤال → جواب
- فروشنده: هر فروش → پیام «🛒 فروش ثبت شد» با موجودی باقی‌مانده
- موجودی ≤ ۳ → «⚠️ موجودی کم است»، صفر → «❌ این محصول تمام شد»
- سؤال نیازمند انسان → مشتری پیام ارجاع می‌گیرد و فروشنده اعلان با متن سؤال

## ۴. امنیت

| لایه | چه می‌کند |
|---|---|
| سکرت در مسیر URL | `/telegram/webhook/<secret>`؛ بدون آن هیچ درخواستی پذیرفته نمی‌شود |
| هدر `X-Telegram-Bot-Api-Secret-Token` | با همان سکرت مقایسه می‌شود، **زمان‌ثابت** (ضد timing attack) |
| `update_id` یکتا | تلگرام اگر ۲۰۰ نگیرد همان آپدیت را دوباره می‌فرستد؛ ما فقط یک‌بار پردازش می‌کنیم |
| بدون AuthGuard | تلگرام توکن ما را ندارد؛ این مسیر فقط با سکرت محافظت می‌شود و هیچ داده‌ی فروشگاهی برنمی‌گرداند (فقط `{ok:true,…}`) |
| `@SkipThrottle` | Throttler سراسری (۱۰۰ در دقیقه) پیام‌های تلگرام را نمی‌بندد |
| ارجاع بی‌حدس | پیام مشتری هرگز اجرا نمی‌شود؛ فقط از `answerFresh` رد می‌شود |
| چت فروشنده | هرگز پاسخ خودکار مشتری نمی‌گیرد؛ فقط اعلان |

**پاسخ همیشه ۲۰۰ است** — حتی وقتی پردازش خطا بدهد — چون تلگرام در غیر این صورت
همان آپدیت را با تأخیر باز می‌فرستد و صف عقب می‌افتد.

## ۵. محدودیت‌ها (صادقانه)

- **پلن Free رندر می‌خوابد.** اولین پیام بعد از ۱۵ دقیقه سکوت، ~۱ دقیقه تأخیر دارد.
  تلگرام webhook را تا ۲۴ ساعت retry می‌کند، پس پیام گم نمی‌شود، ولی تجربه کند است.
  برای فروشگاه واقعی: پلن ۷ دلاری (بدون خواب) یا یک pinger هر ۱۰ دقیقه.
- **بدون صف.** پردازش داخل همان درخواست webhook است (تایم‌اوت تلگرام ۶۰ ثانیه است و
  ما معمولاً چند صد میلی‌ثانیه). با چند هزار پیام در دقیقه به صف نیاز می‌شود.
- **بدون تاریخچه‌ی کامل پیام.** فقط شمارنده و آخرین زمان هر گفتگو ذخیره می‌شود
  (`TelegramConversation`). بایگانی کامل مکالمه عمداً نیست: داده‌ی مشتری کم نگه داشته می‌شود.
- **فقط پیام متنی.** عکس، ویس و استیکر نادیده گرفته می‌شوند (پاسخ نمی‌گیرند).
- **تک‌بات مشترک.** نام و عکس بات برای همه یکی است. برای برند اختصاصی هر فروشگاه،
  توکن هر فروشگاه باید جداگانه اضافه شود (فعلاً در دامنه نیست).
- **دریافت فایل از تلگرام ممکن نیست** روی پلن Free (محدودیت پورت SMTP/شبکه رندر ربطی
  ندارد، ولی برای ارسال فایل/گزارش بزرگ باید به فکر محدودیت ۵۰MB Bot API بود).

## ۶. عیب‌یابی

| نشانه | علت | کار |
|---|---|---|
| `npm run telegram:setup` می‌گوید `Not Found` | توکن غلط یا revoke شده | توکن را از BotFather دوباره بگیر |
| `Wrong response from the webhook: 401` در `--info` | `TELEGRAM_WEBHOOK_SECRET` در سرور با مقداری که webhook ثبت شده یکی نیست | سکرت را یکی کن و `telegram:setup` را دوباره بزن |
| `Wrong response from the webhook: 502/503` | سرویس خواب است یا کرش کرده | لاگ سرویس API در Render |
| مشتری جواب نمی‌گیرد ولی `/start` کار می‌کند | لینک `?start=` بدون کد باز شده | لینک کامل را از پنل کپی کن |
| پنل می‌گوید «بات پیکربندی نشده» | `TELEGRAM_BOT_TOKEN` در سرویس API نیست یا ری‌استارت نشده | env را بگذار و ری‌استارت کن |
| اعلان فروش نمی‌آید | چت فروشنده وصل نیست | تنظیمات → اتصال تلگرام → ساخت کد اتصال |
| `sendMessage … chat not found` | فروشنده بات را بلاک/حذف کرده | دوباره `/start` و کد اتصال تازه |
| اعلان تکراری برای یک فروش | فروش با `Idempotency-Key` تکراری ثبت شده | درست است؛ فروش دوباره ثبت نشده |

## ۷. تست بدون توکن واقعی

کل جریان با یک سرور جعلی تلگرام تست می‌شود (`TELEGRAM_API_BASE`):

```bash
npm test        # با دیتابیس: ۴۰ تست، شامل ۱۳ تست تلگرام
```

تست‌ها: `getMe`/`setWebhook`، `/start` با کد، پاسخ قیمت از موجودی واقعی، پاسخ ارسال،
ارجاع + اعلان به فروشنده، تکرار `update_id`، چت فروشنده، استیکر، اتصال فروشنده با کد
یک‌بارمصرف، اعلان فروش/موجودی کم/تمام‌شده، و اینکه خطای تلگرام جریان را نمی‌شکند.
